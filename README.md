## 一、需求目标和范围

新版 AI 生图的美工版和运营版目前只能上传本地参考图。本需求增加产品库选图能力，使用户可以按当前任务系统 SKU 直接查看和多选产品库图片，并与本地图片共同组成 1～5 张有序参考图。

本期覆盖以下六个入口：

| 业务端 | 新增任务抽屉 | 编辑任务抽屉 | 建任务列表 |
|---|---|---|---|
| 美工版 | 增加“从产品库选择” | 增加“从产品库选择” | 增加“产品库选图” |
| 运营版 | 增加“从产品库选择” | 增加“从产品库选择” | 增加“产品库选图” |

核心规则：

1. 弹窗只查询当前任务已经确定的系统 SKU，不提供任意 SKU 输入或切换。
2. 美工版使用当前查询成功并绑定的系统 SKU；运营版使用店铺 + ASIN 最终命中的同一个 Listing 对象中的系统 SKU。
3. 现有本地点击上传、抽屉文件拖入和复制粘贴能力保持不变；列表原有“+”号仍表示本地上传。
4. 产品库图片和本地图片合并受 1～5 张限制，并在同一参考图区域统一预览、删除和拖拽排序。
5. 列表操作只即时保存参考图字段，不提交任务、不触发生图；抽屉操作只修改草稿，仍需原有保存或提交按钮生效。
6. 产品库卡片和大图不展示图片名称，图片名称不参与分类、排序或选择。

## 二、HTML 原型重点交互

HTML 原型不是静态效果图，以下 ①～⑥ 均已制作完整动态交互。页面顶部和对应区域使用相同编号标注，前端研发应重点体验：

| 标记 | 本期重点 | 原型中可操作内容 |
|---|---|---|
| ① | 六个入口与系统 SKU 失效 | 切换美工版/运营版；体验新增、编辑、列表入口；新增任务查询成功后再修改 SKU、店铺或 ASIN，入口立即置灰；切换到不同系统 SKU 前确认清除旧产品库图片 |
| ② | 产品库弹窗完整状态 | 正常、查询中、无图片、查询失败和重新加载；六个分类切换；跨分类选中状态同步；点击图片进入大图并左右切换、选择或取消 |
| ③ | 1～5 张总量与弹窗外保留 | 顶部场景按钮可切换“混合图片 4/5、已有 5 张可替换、5 张均需保留、当前无参考图”；查看弹窗外保留、已选和剩余数量联动 |
| ④ | 列表即时保存闭环 | 列表选图、上传、删除和排序后的保存中、成功提示；“下次列表保存失败”和弹窗内“下次保存失败”可验证失败回退；清空最后一张前二次确认 |
| ⑤ | 抽屉草稿闭环 | 产品库确认后只写回抽屉并显示“修改尚未保存”；保存任务后才生效；关闭有修改的抽屉时确认放弃 |
| ⑥ | 统一缩略图交互 | 本地和产品库图片混合展示；专用手柄拖拽；列表与抽屉不同的删除确认规则；整张缩略图大图预览及左右切换；来源标识不遮挡预览热区 |

原型中的黄色“原型状态”操作行和顶部场景按钮只用于评审，正式页面不展示。

## 三、产品图片接口和字段映射

### 1. 请求

- 请求方式：`POST`
- 接口：`http://erpapi.zhcxkj.com/Product/ProductImage/GetList`
- 内网接口文档：http://showdoc.zhcxkj.com/web/#/18/6963
- Authorization 授权令牌 Token：联调时私聊产品徐强提供，本文档和代码中不记录真实 Token
- 请求字段：`skus`，字符串数组；本弹窗每次只传当前任务一个系统 SKU
- 稳定关联键：`data[].sku`
- 图片地址：`data[].imageUrl`

请求示例：

```json
{
  "skus": ["22062564"]
}
```

本需求不再传 `isWhiteBackGround: 1`，也不使用 `cosImageUrl` 替代 `imageUrl`。正式页面不得在浏览器代码、日志或仓库中暴露真实 Authorization、Token、Cookie 或其他密钥。

### 2. 响应处理顺序

接口返回的 `data` 是图片对象平铺数组，按以下顺序处理：

1. 只处理 `data[].sku` 与当前任务系统 SKU 精确匹配的对象，不按数组位置推断归属。
2. 去除 `imageUrl` 前后空白；缺失、`null`、空字符串或纯空白 URL 不进入弹窗。
3. 按处理后的完整 `imageUrl` 精确分组，相同 URL 只展示和计数一次。
4. 相同 URL 第一次出现的位置决定图片顺序。
5. 相同 URL 的五个分类字段分别合并：同组任意对象对应字段严格等于布尔值 `true`，图片即命中该分类。
6. 保留去重后图片第一次出现的接口返回顺序，不按分类、文件名或其他字段重新排序。

### 3. 弹窗分类字段对应关系

分类顺序固定为：全部图片、白底图、手持图、尺寸图、场景图、细节图。

| 弹窗分类 | 接口响应字段 | 命中规则 |
|---|---|---|
| 全部图片 | 当前 SKU 的全部有效图片对象 | `imageUrl` 有效并去重后即展示，不要求类型字段 |
| 白底图 | `data[].isWhiteBackGround` | 严格等于布尔值 `true` |
| 手持图 | `data[].isHand` | 严格等于布尔值 `true` |
| 尺寸图 | `data[].isSize` | 严格等于布尔值 `true` |
| 场景图 | `data[].isScene` | 严格等于布尔值 `true` |
| 细节图 | `data[].isDetail` | 严格等于布尔值 `true` |

字段缺失、`null`、`false`、空字符串、数字或其他非布尔真值均不命中对应分类，前端不得根据图片内容、背景颜色或文件名自行推断。

一张图片可以同时命中多个分类；各分类共用同一个选中状态，同一 `imageUrl` 最终只占一张、只计数一次。

`isCover`、`isSpareCover`、`isFigure`、`aiNoHuman`、`aiCharacter` 及其他属性不用于本需求分类、排除、排序或计数。具备有效 `imageUrl` 的图片仍进入“全部图片”。

接口与产品库页面核对结果如下，仅用于验证字段映射，不作为固定配置：

| 系统 SKU | 全部图片 | 白底图 | 手持图 | 尺寸图 | 场景图 | 细节图 |
|---|---:|---:|---:|---:|---:|---:|
| `22062564` | 86 | 8 | 1 | 2 | 41 | 32 |
| `22705034` | 20 | 8 | 1 | 2 | 5 | 2 |

### 4. 接口状态

| 状态 | 页面处理 |
|---|---|
| 查询中 | 骨架屏；分类不可操作且数量显示未加载；禁用确认 |
| 正常无图 | 显示“当前商品暂无可选择的产品库图片”；分类数量为 0 |
| 查询失败或响应异常 | 显示失败提示和“重新加载”；不改变当前参考图 |
| 未选图片加载失败 | 显示失败占位，禁止新增选择，不影响其他图片 |
| 已选图片加载失败 | 继续保留，不自动删除；如需删除，返回参考图区操作 |

业务成功但 `data` 为空数组，或没有当前 SKU 匹配对象，属于正常无图；接口失败、业务状态失败，或 `data` 缺失、为 `null`、不是数组，属于查询失败。

## 四、关键交互规则

### 1. 商品身份变化

1. 新增任务查询成功后，修改美工版系统 SKU，或修改运营版店铺、ASIN，上一组绑定立即失效，产品库入口重新置灰。
2. 改回上一次查询成功的完整取值时可以恢复原绑定，否则必须重新查询成功。
3. 新查询命中不同系统 SKU，且草稿中存在旧系统 SKU 的产品库图片时，查询前提示将清除这些图片。
4. 用户确认并且新查询成功后，清除旧产品库图片；本地图片和来源不明图片继续保留。用户取消时恢复上一组查询条件和参考图。

### 2. 弹窗选择和数量

1. 打开弹窗时，通过当前参考图 URL 与本次有效 `imageUrl` 精确匹配，匹配成功的产品库图片自动选中。
2. 本地图片及本次未匹配图片属于“弹窗外保留”，不在产品库网格中取消，但继续占用 5 张总额度。
3. 点击图片本身只打开大图；右上角勾选区和卡片底部类型标签区负责选择或取消。
4. 达到 5 张后，未选图片仍可预览，但不能继续选择；不得自动替换其他图片。
5. 产品库已选序号只表示产品库已选集合中的顺序，不代表混合本地图片后的最终绝对位置。
6. 临时结果与进入弹窗前的图片 URL 和顺序完全一致时，“确认选择”不可用，不发起列表保存，也不产生抽屉未保存状态。
7. 取消、关闭或非保存状态按 `Esc` 均放弃临时选择；点击弹窗遮罩不关闭。

### 3. 确认结果和最终顺序

1. 弹窗外保留图片继续保留原位置。
2. 原有且仍选中的产品库图片保留原位置。
3. 新选择的产品库图片按首次勾选顺序追加到末尾。
4. 原有产品库图片在同一次弹窗中取消后重新勾选，恢复原位置。
5. 最终结果按完整 `imageUrl` 精确去重，保留当前顺序中第一次出现的位置，总数不得超过 5 张。
6. 产品库弹窗内不排序；确认后在统一参考图区域通过专用手柄调整最终顺序。
7. 列表、抽屉、落库数组和最终提交给生图模型的参考图顺序必须一致。

### 4. 列表和抽屉差异

| 场景 | 处理方式 |
|---|---|
| 列表确认选图、上传、删除、排序 | 只即时保存参考图字段；保存期间禁用重复操作，图片预览仍可使用 |
| 列表保存失败 | 恢复操作前的图片和顺序，提示失败，不得误报成功 |
| 列表删除 | 任何图片均二次确认；最后一张强化提示；本地、产品库、来源不明使用不同恢复说明 |
| 抽屉确认选图、上传、删除、排序 | 只修改当前草稿并显示“修改尚未保存” |
| 抽屉删除 | 不逐张二次确认；随任务保存生效，关闭抽屉时可以放弃全部修改 |

列表清空最后一张并保存成功后，任务转为“待完善”且不能提交生图；从 0 张补充到 1～5 张后，只有其他必填内容也完整时才恢复为“待提交”。

### 5. 历史和权限兼容

1. 历史任务不专项回查、不自动补来源、不自动重排。
2. 历史图片只有在现有来源字段或本次 URL 匹配能够可靠识别时才展示“本地”或“产品库”；来源不明时不展示标识，也不猜测恢复方式。
3. 来源标识不拦截缩略图点击；除拖拽手柄和删除按钮外，整张缩略图均可打开大图。
4. 产品库选图不扩大用户原有业务端、店铺、商品、任务或数据权限。
5. 弹窗、大图和二次确认的键盘焦点停留在当前最上层，关闭后返回原入口。

## 五、验收重点

1. 美工版、运营版新增、编辑、列表共六个入口均可用；无有效系统 SKU 时正确置灰。
2. 请求只传当前系统 SKU 的 `skus`，不传 `isWhiteBackGround`，不暴露真实鉴权信息。
3. 使用 `data[].sku` 关联、`data[].imageUrl` 展示；重复 URL 的顺序和分类字段合并符合本 PRD。
4. 六个分类的字段映射、顺序、数量和跨分类选中同步正确，不展示“其他”。
5. 弹窗外保留、产品库已选、剩余数量和 1～5 张限制正确；无变化不能确认保存。
6. 产品库及参考图大图支持按钮和键盘方向键切换，不展示图片名称。
7. 列表保存成功、失败回退、删除确认和任务状态变化正确；抽屉草稿及放弃修改正确。
8. 本地和产品库图片能够混合拖拽，保存、刷新和重新编辑后顺序一致。
9. 查询中、无图、查询失败、重新加载、单图失败和已选失败图片保护均符合本 PRD。
10. 现有本地上传、批量导入、AI 视频、自动取图策略以及审核、生成、查询和推送流程不受影响。
